# LAB7 – Hypothesis Fuzz Testing

## Objective

The objective of this lab is to use **Hypothesis** for fuzz testing a Python program. The original program assumes that all user inputs are valid. By generating random inputs, Hypothesis helps identify cases where the program crashes. The identified bugs are then fixed so that every function can safely handle any input without raising an exception.

## Running the Program

Execute the parser module:

```bash
python bike_share_rental_parser.py
```

---

## Running the Tests

Run the Hypothesis tests using:

```bash
pytest test_bike_share_rental_parser.py
```

---

## Testing Process

1. Run the original program and observe that it crashes for invalid inputs.
2. Execute the Hypothesis tests on the buggy implementation.
3. Identify the failing test cases generated by Hypothesis.
4. Modify the parser functions to safely handle invalid inputs.
5. Run the tests again until all tests pass successfully.

---

## Bugs Found

### 1. parse_ride_duration()

- Crashed when input was `None`.
- Crashed when the input did not contain exactly one colon.
- Crashed when hours or minutes were not numeric.

**Fix:** Added input validation and exception handling, returning a default value for invalid input.

---

### 2. format_station_code()

- Crashed when input was `None`.
- Crashed on empty strings because of indexing.

**Fix:** Checked for invalid or empty input before accessing characters.

---

### 3. parse_ride_log()

- Crashed when input was `None`.
- Crashed when fewer than three comma-separated fields were present.
- Crashed when the minutes field was not an integer.

**Fix:** Validated the input format and used exception handling while converting minutes.
